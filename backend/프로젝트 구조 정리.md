## 엔티티 지도 — 전체 관계

```
[기준 데이터 — 미리 등록]
Material ──────────────────────────── InspectionStandard
(품목 종류)                              (검사 기준서)
 · modelName: "ER-2000 SMART"           · material FK
 · partName: "배터리팩"                  · rev: 2 (개정 번호)
 · partCode: "BAT-001"                       │
                                        InspectionItem
                                        (검사 항목)
                                         · itemName: "전압측정"
                                         · measurementType: NUMERIC
                                         · minValue: 3.6
                                         · maxValue: 3.8
                                         · unit: "V"

[생산 실행 — 매일 발생]
ProductionPlan ──── ProductionLot ──── LotInspectionResult
(일별 목표)          (완제품 1개)        (항목별 검사 결과)
 · modelName         · plan FK          · lot FK
 · planDate          · lotNo: 3         · inspectionItem FK
 · targetQty: 50     · status:          · round: 1
 · passCount: 12       IN_PROGRESS      · result: PASS / NG
 · status:             PASS             · measuredValue: 3.72
    PLANNED            FAIL             · memo
    IN_PROGRESS
    COMPLETED
```

## 엔티티 역할 한 줄 요약

| 엔티티 | 역할 | 언제 생성 |
|---|---|---|
| `Material` | 품목 종류 마스터 | 관리자가 등록 (1회) |
| `InspectionStandard` | 해당 품목의 검사 기준서 | 관리자가 등록, 개정 시 rev 증가 |
| `InspectionItem` | 기준서 안의 개별 검사 항목 | 기준서 등록 시 함께 |
| `ProductionPlan` | 오늘 ER-2000을 50개 만든다 | 매일 아침 등록 |
| `ProductionLot` | 완제품 1개 생산 단위 | 작업자가 "Lot 시작" 클릭 시 |
| `LotInspectionResult` | 이 Lot의 이 항목 검사 결과 | 검사 제출 시 자동 생성 |

---

## 서비스 역할

**`InspectionService`** — 기준서 관리
- 품목에 기준서 등록, 항목 추가/수정/삭제
- 개정 시 rev 올리고 RevisionHistory 기록
- 이전 rev 항목은 `deletedAtRev`로 소프트 삭제

**`ProductionPlanService`** — 계획 관리
- 날짜별 생산 계획 등록·조회
- 단순 CRUD

**`ProductionService`** — 핵심 로직
- `startLot()`: Lot 생성, 계획 상태 IN_PROGRESS로 전환
- `submitBatchResults()`: 검사 항목 일괄 제출 → 자동 판정 → Lot 상태 갱신
- `evaluateAndUpdateLotStatus()`: 모든 항목 PASS이면 Lot PASS, Plan passCount++
- `failLot()`: 작업자가 수동 불합격 처리

**`DashboardService`** — 대시보드 집계
- 날짜 기준 계획 목록 조회
- 각 계획의 Lot 수, 진행중/불합격 수, NG 횟수, 재검사 횟수, 합격률 집계

## 데이터 흐름 — Lot 1개 완료까지

```
1. 관리자: Material 등록 (LCD, 배터리, 버튼스위치)
2. 관리자: 각 Material에 InspectionStandard + InspectionItem 등록
           (항목 3개: 전압 3.6~3.8V, 외관, 클릭감)

3. 작업자: 오늘 ER-2000 50개 목표 → ProductionPlan 생성

4. 작업자: "Lot 시작" 클릭
           → ProductionLot 생성 (status: IN_PROGRESS)

5. 작업자: 화면에 모든 검사항목 펼쳐짐
           - 전압측정: [3.72 입력]
           - 외관검사: [PASS 선택]
           - 클릭감:   [PASS 선택]
           → "검사 결과 일괄 제출" 클릭

6. 서버: LotInspectionResult 3개 생성
         - 전압 3.72 → min 3.6 ~ max 3.8 → 자동 PASS
         - 외관 → PASS
         - 클릭감 → PASS
         → 전체 PASS → Lot.status = PASS
         → Plan.passCount++ (1/50)

7. 프론트: 자동으로 다음 Lot 검사 화면 진입 (같은 계획)
```

---

## NG 발생 시 흐름

```
5'. 전압 3.1V 입력 → min 3.6 미달 → 자동 NG
    → Lot 여전히 IN_PROGRESS

6'. 화면에 전압측정 항목만 빨간 배경으로 남음 (나머지 PASS는 잠김)
    → 작업자: 새 배터리로 교체 후 3.74V 재입력
    → "재검사 제출" → round 2로 PASS
    → 전체 PASS → Lot PASS
```

## 패키지 의존 방향

```
global ← user ← auth
global ← material
global ← inspection → material, user
global ← production → inspection, material
```

- `global`: 공통 응답, 에러, JWT, 보안 설정
- `production`이 `inspection`과 `material`을 참조하지만 역방향은 없음
- Service끼리 직접 Repository 교차 주입 금지 — 반드시 해당 도메인 Service를 통해서만
