# 개별 부품 인스턴스 방식 전환 수정안

## 목적

현재 시스템은 작업자가 lot 검사 시점에 측정값을 직접 입력한다.
변경 목표는 부품 입고 시 측정값을 미리 DB에 저장해두고,
생산 시 lot에 부품을 배정하면 시스템이 자동으로 기준값과 비교해 판정하는 구조다.

---

## 현재 구조 요약

```
Material (품목 종류 마스터 — LCD 1행)
  └── InspectionStandard (검사 기준서)
        └── InspectionItem (검사항목 — minValue, maxValue)

ProductionLot
  └── LotInspectionResult (작업자가 실측값 입력 → 판정)
```

---

## 변경 후 구조

```
Material (품목 종류 마스터 — 유지)
  └── InspectionStandard (검사 기준서 — 유지)
        └── InspectionItem (검사항목 — minValue, maxValue — 유지)
  └── MaterialInstance (개별 부품 인스턴스 — 신규)
        - serialNo: String (입고 시 부여)
        - measuredValue: BigDecimal (입고 검사 시 측정한 실측값)
        - status: Enum (AVAILABLE / ASSIGNED / REJECTED)

ProductionLot
  └── LotMaterialAssignment (lot ↔ instance 연결 — 신규)
        - lot FK
        - instance FK
        └── 자동 판정 결과 (instance.measuredValue vs InspectionItem 기준 비교)
```

---

## 추가할 엔티티

### MaterialInstance

| 필드 | 타입 | 설명 |
|---|---|---|
| id | Long | PK |
| material | Material FK | 품목 종류 |
| serialNo | String | 개별 시리얼 번호 |
| measuredValue | BigDecimal | 입고 시 실측값 (nullable — VISUAL 항목은 없음) |
| status | Enum | AVAILABLE / ASSIGNED / REJECTED |
| createdAt | LocalDateTime | 입고 등록 시각 |

### LotMaterialAssignment

| 필드 | 타입 | 설명 |
|---|---|---|
| id | Long | PK |
| lot | ProductionLot FK | |
| instance | MaterialInstance FK | |
| result | InspectionResultCode | PASS / NG (자동 판정) |
| evaluatedAt | LocalDateTime | 판정 시각 |

## 삭제하거나 역할 변경할 것

- `LotInspectionResult` → 삭제 (작업자 입력 방식 제거)
- `ProductionService.submitResult()` → 삭제
- `ProductionService.submitBatchResults()` → 삭제
- `InspectionResultRequest` DTO → 삭제
- 프론트 검사 입력 폼 → 삭제, lot에 부품 배정 UI로 교체

## 새로 추가할 API

### 부품 인스턴스 등록 (입고 시)
```
POST /api/materials/{materialId}/instances
Body: [
  { "serialNo": "LCD-A001", "measuredValue": 3.72 },
  { "serialNo": "LCD-A002", "measuredValue": 3.65 },
  ...
]
```

### Lot에 인스턴스 배정 + 자동 판정
```
POST /api/production/lots/{lotId}/assign
Body: { "instanceIds": [1, 2, 3, ...] }
Response: LotDetailResponse (각 인스턴스 판정 결과 포함)
```

### Lot 상세 (배정된 인스턴스 + 판정 결과)
```
GET /api/production/lots/{lotId}
```

---

## 자동 판정 로직 (변경 없음 — 위치만 이동)

```
instance.measuredValue 가 InspectionItem.minValue ~ maxValue 범위 내 → PASS
범위 밖 → NG (해당 instance status = REJECTED, 재입고 또는 교체 필요)
모든 배정 인스턴스 PASS → Lot PASS
```

---

## 프론트 변경 포인트

- `LotInspectionView` 검사 입력 폼 → 제거
- 새 UI: 배정 가능한 인스턴스 목록 표시 → 선택 → "배정 및 판정" 버튼
- 결과 화면: 각 인스턴스별 측정값 + PASS/NG 표시
- NG 인스턴스: 교체 후 새 인스턴스 재배정

## 시드 데이터 전략

DataInitializer에서 각 Material마다 수십~수백 개 인스턴스를 미리 생성.
measuredValue는 기준 범위 내 값 위주로, 일부 의도적으로 범위 밖으로 설정해 NG 시나리오 포함.

```java
// 예시: 배터리 인스턴스 100개 생성
// 기준: 3.6 ~ 3.8V
// 95개는 범위 내 난수, 5개는 범위 밖 (NG 시나리오)
```

## 작업 순서 (AI 지시용)

1. `MaterialInstance` 엔티티 + 레포지토리 생성
2. `LotMaterialAssignment` 엔티티 + 레포지토리 생성
3. `MaterialInstanceService` — 인스턴스 일괄 등록, 조회
4. `ProductionService.assignInstances()` — 배정 + 자동 판정 + Lot 상태 갱신
5. `LotDetailResponse` 수정 — 배정 인스턴스 + 판정 결과 포함
6. 기존 `submitResult`, `submitBatchResults` 제거
7. Controller 엔드포인트 교체
8. DataInitializer 인스턴스 시드 데이터 추가
9. 프론트 `LotInspectionView` 교체 — 인스턴스 배정 UI
